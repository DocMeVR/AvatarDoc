## Layers

The FX animator of an avatar is a list of layers. Each layer has states, and each state plays an animation that sets objects, blend shapes and materials. The layers play together. When two of them set the same thing, the layer that sits later in the list decides it. AvatarDoc builds its layers with this in mind.

Every toggle, radial, exclusive group and condition trigger gets its layers from AvatarDoc, named **AD:** and the entry's name. The other layers add a word in brackets after the name, such as (preset), (shape), (flip), (distance) or (pin), and a layer that follows a shape has its own name. A merged animator keeps the layer names of its own controller. [Limits](../../reference/limits/#what-it-adds-to-the-fx-controller) counts the layers.

### The order of the layers

When the build is finished, the layers of the FX controller stand in this order, from first to last:

1. the avatar's own FX layers
2. AvatarDoc's toggle and condition trigger layers, with the toggles, exclusive groups and radials in menu order
3. AvatarDoc's preset, touch and follow layers
4. the merged animators, both AvatarDoc's own and Modular Avatar's
5. the Fade and blend shape trigger layers, and after them all the pin layers

Layers that VRCFury adds land before the last step too. AvatarDoc moves the pin layers to the end only in its last pass, after every other tool has run. See [Pin layers go last](#pin-layers-go-last).

When an entry that starts on holds a shape, the last pass also adds the rest layer, right after the first three layers. See [The rest layer](#the-rest-layer).

An ordinary layer is simple:

- A toggle's layer has an off state and an on state. The animation of each state sets every target of the toggle. The on state sets the on values. The off state sets the values the targets have in your scene, or the off value you chose.
- An exclusive group has one layer with an off state and one state for each toggle. A state sets its own toggle's targets on and the targets of the other toggles off.
- A radial has one state that blends between the value at the low end and the value at the high end.

## Write Defaults

Write Defaults is a setting of each animator state. When it is on, the state hands everything that its layer ever animates back to what an earlier layer sets, or else to its starting value, unless the state sets it itself. When it is off, the state sets only what its own animation sets.

AvatarDoc chooses one setting for all its ordinary layers, so that they match the rest of your avatar:

- It reads the states of the avatar's own FX layers. When every state agrees, AvatarDoc uses that setting.
- When they disagree, or when there are no states, AvatarDoc uses Write Defaults on. A warning names the layers that mix the two settings, and the header of the inspector shows what AvatarDoc uses.
- It does not count additive layers, layers that are one state holding a blend tree, or its own pin layers.

A merged animator keeps the Write Defaults of its own controller, unless <Label k="ad.ui.animator.match_write_defaults" /> is on, which it is by default. Then its layers follow the avatar's setting. An additive layer, and a layer that is one state holding a direct blend tree, keep Write Defaults on either way, because they stop working without it.

## Pin layers

Some layers must not use Write Defaults. These are the pin layers:

- the second layer of a toggle or a trigger that holds a shape with <Label k="ad.ui.seg.pin" />, or with a Hold the rest rule
- the layer of a blend shape trigger
- the layer of a touch trigger in <Label k="ad.ui.touch.follow" /> mode
- the shared layers that pause blinking and lip sync

The second layer of a toggle or a trigger is named like its main layer, with (pin) after it. The pause layers are named **AD: Blink pause** and **AD: Lip sync pause**. Every state of a pin layer has Write Defaults off, whatever the rest of the avatar uses.

### Why Write Defaults is off

A pin layer sits last in the list (see [The order of the layers](#the-order-of-the-layers)), so it wins over face tracking and gestures while its entry is on. When the entry is off, the layer must let go. With Write Defaults on, its off state would write the starting value of the shape on every frame, from the last layer, and freeze face tracking and blinking on that value. With Write Defaults off, a state writes only what it has a curve for. The off state of a pin layer has no curve for any shape the layer holds, so while the entry is off those shapes are free for face tracking, blinking, gestures and your other toggles.

### A resting pin layer weighs nothing

One layer with Write Defaults off and a weight above 0 is enough to make the whole FX controller keep every face shape that something outside it animates. The dance of an MMD world is such an animation, so it could not move the face. So a pin layer weighs nothing while it rests. Its off state sets the layer's weight to 0, again every 3 seconds, and each on state sets it back to 1, through an animator layer control aimed at the layer itself. Load and Reset play at full weight, so the moment of rest still counts. The pause layers animate nothing, so they weigh 0 all the time. Their tracking changes work at any weight.

A layer at weight 0 shows each shape and object the way your avatar was uploaded, unless an earlier layer sets it. So a pin layer only rests at weight 0 when every value it rests at is the uploaded one, or one that another layer writes on every frame anyway, such as the shape of an ordinary toggle or of [the rest layer](#the-rest-layer).

A pin layer keeps its weight while it rests, and still stops the dance, when it rests anywhere else:

- a row with <Label k="ad.ui.target.explicit_off" />
- an object that is off while the entry rests but on in your scene
- a blend shape trigger that starts on and switches objects or materials, which go into the uploaded avatar the way they start

While an entry with a pin layer is on, a world's dance can't move the face either. See [My face does not move in an MMD world](../../help/troubleshooting/#mmd-face).

### The rest layer

The uploaded avatar shows how your entries start, the shapes that pin layers hold included. So people who don't see your animations, because their Safety settings turn them off for you, see the same look as everyone else when the avatar loads.

Those shapes rest away from the uploaded value, though. So AvatarDoc adds one layer for them, named **AD: Rest**. Its only state has Write Defaults on and writes the rest of each such shape on every frame: its weight in your scene, or the start value of another toggle that sets it without holding it. Gestures, face tracking and the pin layers come later in the list. They decide the shape while they play, and let it go back to the rest when they stop. That is how the pin layer of a toggle that is <Label k="ad.ui.default_on" />, of a group's default member or of a blend shape trigger that starts on rests at weight 0 too. Modular Avatar rests what its own components change in the same way.

A pin layer whose entry is on wins over every other layer, so the uploaded avatar shows the held value even when a later toggle in the menu sets the same shape. A shape that Modular Avatar's Blendshape Sync, VRCFury's Blendshape Link or an AvatarDoc Shapes Follow row copies from a held shape gets the look and the rest of its source too, so the outfit and the body still match.

AvatarDoc writes those shapes into the uploaded avatar only in its last pass, after Modular Avatar and VRCFury. Until then the scene keeps their rest, which is the value those tools read when they work out the rest of what they change themselves.

The rest layer goes right after the first three layers of FX. MMD worlds switch those three off, and Modular Avatar and VRCFury keep their MMD layers there, so AvatarDoc moves none of them. When FX has fewer than three layers before AvatarDoc's own, the rest layer comes right after those, where an MMD world can switch it off during a dance. d4rk Avatar Optimizer and Avatar Optimizer (AAO) don't merge the rest layer into their own layers, because the pin layers animate the same shapes.

Some shapes keep their rest in the uploaded avatar instead:

- a shape VRChat blinks or speaks with, because VRChat stops moving a shape that any layer writes, so the rest layer leaves it out
- a shape that one of the first three layers moves, such as a gesture there, because the rest layer would come after that layer and hide it, so the rest layer leaves it out too
- the source shape of a blend shape trigger in <Label k="ad.ui.trigger.mode.replace" /> mode, because the trigger takes every animation of that shape away, so the shape shows the uploaded value for good

While its entry is off, a world's dance can't move a shape that the rest layer writes, and neither can your avatar's own Action or Gesture layer, such as an emote, because FX comes after them. A dance still moves every other shape, because the rest layer has Write Defaults on.

Up to AvatarDoc 0.8.2 the held shapes went into the uploaded avatar without a rest layer. The pin layer then kept its weight while it rested, and a gesture face on the same shape stayed after the gesture ended.

### Explicit rests

A layer that stops writing a shape leaves it at the last value it was given. A pinned smile would stay when the toggle goes off, if nothing else moved the shape.

So a pin layer resets once, then lets go. On its way from on to off, it passes a short state named **Reset**. Reset plays for a moment, 1/60 of a second (one frame at 60 frames a second, a few at higher frame rates), and sets each shape the layer held back to its rest: the value it has in your scene, or the row's off value when it has one. Then the layer moves on to its off state, which writes nothing for those shapes. From then on, whatever else moves a shape decides it: face tracking, blinking, a gesture or another toggle. A shape that nothing else moves stays at its rest.

The layer also resets once when the avatar loads: it starts in a state named **Load**, which plays the same moment of rest and passes on to Reset. So the avatar loads with these shapes at rest whenever the saved choice is off.

At the very end of the build, when every layer from every tool is in the controller, AvatarDoc fills in each Reset. Every shape the layer held goes in, even one that another layer moves, such as face tracking or a gesture. A layer with Write Defaults off keeps the last value it wrote until something writes over it, and on other players' copies of your avatar that other layer did not always do so: a pat's closed eyes stayed closed. Where the other layer runs, it writes over the moment of rest straight away.

For each material property that a pin layer writes, AvatarDoc first asks whether another layer owns it. Another layer owns it when it is not additive, its weight is higher than 0, no animator layer control can fade it, and one of these is true:

- every state of the layer has Write Defaults on, and the layer animates the property somewhere
- every animation the layer can play has a curve for the property
- a direct blend tree of the layer has a child with a curve for the property, which is how face tracking is built

If another layer owns the property, Reset leaves it out, so a moment of rest never hides a toggle that moves the same property. If no layer owns it, Reset sets it back to its rest. This guess can be wrong on a real avatar: a layer that another layer can fade, or one that rests in an empty state, does not count as an owner. A wrong guess costs that moment at most, because Reset and Load are the only states that write the rest value, and only at load and on the way out. A layer whose Reset has nothing to set has neither state, and goes straight from on to off.

The same rule hands back the material properties that a <Label k="ad.ui.touch.hold" /> trigger or a <Label k="ad.ui.touch.follow" /> trigger changes. On an avatar with Write Defaults off, the layer of a <Label k="ad.ui.touch.hold" /> trigger that changes a property passes a Reset state too. On an avatar with Write Defaults on, that layer's off state writes the property on every frame anyway, so it holds the property at rest the whole time the trigger does not fire.

### Off values

A row's own off value, set with <Label k="ad.ui.target.explicit_off" />, is its rest. A toggle's layer holds it the whole time the toggle is off, and so does a <Label k="ad.ui.touch.hold" /> trigger's layer for a blend shape row. A trigger in <Label k="ad.ui.touch.follow" /> mode, a blend shape trigger, and a <Label k="ad.ui.touch.hold" /> trigger's property row on an avatar with Write Defaults off set it when the avatar loads and every time the effect ends; while the trigger rests, the value stays unless something else moves it. On an avatar with Write Defaults on, a <Label k="ad.ui.touch.hold" /> trigger's layer holds a property's off value the whole time it rests.

Three details:

- When several layers hold one shape, each of them resets it once on its own way out, so the shape goes back to rest whichever of them turns off last. While a lower layer still holds the shape, an upper layer that turns off covers it for that moment only. When two layers rest one property at different off values, the value after both are off is the one of the layer that turned off last, and at load the one of the later layer.
- An exclusive group goes from one member to the next through Reset and its off state, so each member state sets only its own shapes. Switching members takes a frame or two.
- An exclusive group has one pin layer for all its members, and it keeps its weight while a member that holds shapes is on. A gesture face on another member's shape stays in that time after the gesture ends.

A shape that VRChat blinks or speaks with rests at 0 for the moment of Reset, whatever its weight in your scene, then VRChat's blinking or lip sync has it again. See [Blinking, lip sync and face tracking](../blinking-and-lip-sync/).

### Pin layers go last

AvatarDoc builds its layers before Modular Avatar and VRCFury run. A layer that they add later would take a shape back from a pin layer. So AvatarDoc gives each pin layer the highest priority, and in its last pass it moves every pin layer to the end of the FX controller. It moves only the layers it made itself, found by their exact names. It also points a layer control of another controller at the same layer as before, because such a control names a layer by its place in the list.

VRCFury has a Write Defaults fixer that can turn Write Defaults on for every layer. In its last pass, AvatarDoc turns it off again for its own pin layers. This is why [the page about VRCFury and Modular Avatar](../../guides/with-vrcfury-and-modular-avatar/) says to choose **Skip** in the fixer.

## Hold the rest keeps only what is needed

A Hold the rest rule starts by writing every other shape of the mesh. A face can have hundreds of shapes, and most of them never move. In its last pass, once every tool has added its layers, AvatarDoc removes the curves of the shapes that nothing moves, because those shapes already show the value the rule would hold them at. It keeps a curve when:

- an animation of any controller of the avatar moves the shape, or an override pins it
- the rule holds at 0 a shape that is not at 0 in your scene
- the shape is one that VRChat blinks or speaks with, and the rule's switch for it is on

A note says how many shapes the rule holds in the end. The note in the inspector says "up to" for this reason. A shape that only something outside the avatar moves, such as a dance in an MMD world, is not held. [Hold the rest of a face](../../guides/hold-the-rest/) shows the controls.

## When two pieces hold one shape

[AvatarDoc Shapes](../../reference/avatardoc-shapes/#when-two-pieces-hold-one-shape) writes into animations that other layers play. When two pieces hold one shape and different layers switch them, the later layer decides the shape, because of the rule at the top of this page. A warning names the pair. Put both pieces on one toggle or in one exclusive group to avoid it.
