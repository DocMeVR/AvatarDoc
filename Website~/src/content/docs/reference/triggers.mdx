## When to use it

A trigger is a rule. It turns its effects on while its condition is true, with no button in the menu and no synced bits. Use it when something should follow a state the avatar already has: hide the hair while the hat is on, blush while the right hand shows a thumbs up, change the face only while sitting.

This page covers triggers that follow a toggle or a parameter, and the parts every trigger shares: the conditions, the groups and <Label k="ad.ui.trigger.gate" />.

- For a touch or a PhysBone, see [Touch triggers](../touch-triggers/).
- For a shape that moves smoothly, see [Blend shape triggers](../blend-shape-triggers/).
- For a button that switches things itself, use a [toggle](../toggle/).

To add a trigger, press <Label k="ad.ui.add.trigger" /> in the toolbar. On a narrow inspector, it sits under <Label k="ad.ui.more" />. Only Advanced mode can add a trigger. A trigger that exists shows its whole panel in both modes; in Simple mode, the panel starts with a note that it is an advanced item. Triggers sit under <Label k="ad.ui.triggers" /> at the end of the tree, where each row shows a short form of its condition when the tree is at least 360 pixels wide.

## Settings

The settings in the order the panel shows them.

### Name [#name k=ad.ui.name]

**Shown in:** Simple and Advanced · **Default:** New Trigger · **Choices:** any text

The trigger's name in the tree and in messages. A trigger has no button in the menu, so its name has no style row.

### When [#when k=ad.ui.trigger.when]

**Shown in:** Simple and Advanced, while the trigger has one condition · **Default:** <Label k="ad.ui.trigger.source.toggle" /> · **Choices:** <Label k="ad.ui.trigger.source.toggle" />, <Label k="ad.ui.trigger.source.parameter" />, <Label k="ad.ui.trigger.source.blendshape" />, <Label k="ad.ui.trigger.source.contact" />, <Label k="ad.ui.trigger.source.physbone" />

What starts the trigger. The fields under it change with the choice. Once <Label k="ad.ui.when.add_and" /> or <Label k="ad.ui.when.add_or" /> adds a group, <Label k="ad.ui.trigger.when" /> goes away and each row in the groups picks its own kind. When removing rows leaves one condition, the groups go away and <Label k="ad.ui.trigger.when" /> comes back with that condition. A blend shape trigger always keeps <Label k="ad.ui.trigger.when" />.

### Toggle [#toggle k=ad.ui.trigger.toggle]

**Shown in:** Simple and Advanced, with <Label k="ad.ui.trigger.source.toggle" /> · **Default:** none picked · **Choices:** every toggle of every AvatarDoc component on the avatar

The toggle the trigger follows. A toggle of another component shows that component's object name beside it. The list under it chooses <Label k="ad.ui.trigger.toggle.on" />, the default, or <Label k="ad.ui.trigger.toggle.off" />.

When the avatar has no toggle at all, the list shows <Label k="ad.ui.trigger.no_toggles" /> and is greyed out: add a toggle first.

A toggle on a component that is switched off is not built, so a note says the trigger will not fire.

### Parameter [#parameter k=ad.ui.trigger.parameter]

**Shown in:** Simple and Advanced, with <Label k="ad.ui.trigger.source.parameter" /> · **Default:** empty · **Choices:** any parameter name

The parameter the trigger watches, such as GestureRight. Type the name, or press the arrow button at the right end. The list has a search field and groups the parameters by where they come from, each with its type:

- <Label k="ad.ui.pick.parameter.avatar" />: the avatar's own parameters and those its components provide.
- <Label k="ad.ui.pick.parameter.doctor" />: the parameters AvatarDoc plans for its own controls.
- <Label k="ad.ui.pick.parameter.vrchat" />: VRChat's own, such as GestureLeft or Seated.
- <Label k="ad.ui.chip.vrcfury" />: VRCFury toggles that use a global parameter, when the avatar has any.

A parameter that nothing on the avatar declares is read as a Float, and a warning says so.

### Condition [#condition k=ad.ui.trigger.condition]

**Shown in:** Simple and Advanced, with <Label k="ad.ui.trigger.source.parameter" /> · **Default:** <Label k="ad.ui.trigger.condition.is_true" /> · **Choices:** <Label k="ad.ui.trigger.condition.is_true" />, <Label k="ad.ui.trigger.condition.is_false" />, <Label k="ad.ui.trigger.condition.equals" />, <Label k="ad.ui.trigger.condition.not_equals" />, <Label k="ad.ui.trigger.condition.greater" />, <Label k="ad.ui.trigger.condition.less" />

How the parameter's value must compare. For a parameter that is on or off, use <Label k="ad.ui.trigger.condition.is_true" /> or <Label k="ad.ui.trigger.condition.is_false" />. For a number, the other four compare it with <Label k="ad.ui.trigger.value" />.

On a whole number, <Label k="ad.ui.trigger.condition.is_true" /> means not 0. On a Float, it means more than 0.5, and <Label k="ad.ui.trigger.condition.equals" /> means within 0.005 of the value.

### Value [#value k=ad.ui.trigger.value]

**Shown in:** Simple and Advanced, with <Label k="ad.ui.trigger.condition.equals" />, <Label k="ad.ui.trigger.condition.not_equals" />, <Label k="ad.ui.trigger.condition.greater" /> or <Label k="ad.ui.trigger.condition.less" /> · **Default:** 0 · **Choices:** any number

The number the condition compares with. GestureRight <Label k="ad.ui.trigger.condition.equals" /> 7 is true while the right hand shows a thumbs up.

### Mode [#mode k=ad.ui.touch.mode]

**Shown in:** Simple and Advanced, with <Label k="ad.ui.trigger.source.parameter" />, while the first parameter is a Float or the trigger is already in <Label k="ad.ui.touch.follow" /> mode · **Default:** <Label k="ad.ui.touch.hold" /> · **Choices:** <Label k="ad.ui.touch.hold" />, <Label k="ad.ui.touch.follow" />

- <Label k="ad.ui.touch.hold" />: the effects are on while the conditions are true, and off the moment they are not.
- <Label k="ad.ui.touch.follow" />: the effects blend in with the first parameter's value, from 0 to <Label k="ad.ui.touch.fullat" />, while the trigger's other conditions are true. The first parameter has no <Label k="ad.ui.trigger.condition" /> then: its value itself moves the effects. Use it for a value between 0 and 1, such as GestureLeftWeight, how hard the left hand squeezes: the trigger on Index controllers, the grip on most other controllers. The [Gesture faces window](../gesture-faces-window/) uses it for <Label k="ad.ui.gestures.fist" />.

A parameter that is on or off, or a whole number, has no value in between to follow, so its trigger does not show <Label k="ad.ui.touch.mode" />.

### Fully on at [#fully-on-at k=ad.ui.touch.fullat]

**Shown in:** Simple and Advanced, in <Label k="ad.ui.touch.follow" /> mode on a parameter · **Default:** 0.8 · **Range:** 0.05 to 1

The value of the first parameter at which the effects are fully on. Above 0 they start to show, and between 0 and this value they blend.

### Fires [#fires k=ad.ui.fires]

**Shown in:** Simple and Advanced

The line that spells out the whole rule, built from every condition, such as When "Hat" is on, and only while "Hair hiding" is on. The summary prints the same sentence.

### + And [#add-and k=ad.ui.when.add_and]

**Shown in:** Simple and Advanced

Adds a condition that must also be true. The first press moves the trigger's condition into a group, a box captioned <Label k="ad.ui.when.all_of" />, and adds a new row to it, set to <Label k="ad.ui.when.kind.toggle" />. Each group has its own <Label k="ad.ui.when.add_and" />.

A group holds at most 4 conditions. The button switches off at 4, and its tooltip says to start another group with <Label k="ad.ui.when.add_or" />.

### + Or [#add-or k=ad.ui.when.add_or]

**Shown in:** Simple and Advanced, on a trigger that follows a toggle, a parameter, or a touch in <Label k="ad.ui.touch.hold" /> or <Label k="ad.ui.touch.flip" /> mode

Adds another group: one more way the trigger can fire. <Label k="ad.ui.when.any_of" /> sits between the groups. The trigger fires while any group is fully true, and a group is true while all of its conditions are.

Use at most 4 groups of 4 conditions each. A larger rule, or one that would need more than 64 ways to turn the trigger back off, is refused with an error that names the counts.

### Rows in a group [#rows]

**Shown in:** Simple and Advanced, once the trigger has groups · **Default:** a new row is a <Label k="ad.ui.when.kind.toggle" /> condition · **Choices:** <Label k="ad.ui.when.kind.toggle" />, <Label k="ad.ui.when.kind.parameter" />, <Label k="ad.ui.when.kind.contact" />, <Label k="ad.ui.when.kind.physbone" />

Each row starts with a list that picks its kind, and an x that removes it. The x on a group's caption line removes the whole group.

- A <Label k="ad.ui.when.kind.toggle" /> row has <Label k="ad.ui.trigger.toggle" />, which starts at <Label k="ad.ui.when.pick_toggle" />, and <Label k="ad.ui.trigger.toggle.on" /> or <Label k="ad.ui.trigger.toggle.off" />.
- A <Label k="ad.ui.when.kind.parameter" /> row has <Label k="ad.ui.trigger.parameter" />, <Label k="ad.ui.trigger.condition" /> and <Label k="ad.ui.trigger.value" />, as described on this page.
- A <Label k="ad.ui.when.kind.contact" /> or <Label k="ad.ui.when.kind.physbone" /> row shows its condition in words and a <Label k="ad.ui.when.settings" /> button. The button opens its settings, which [Touch triggers](../touch-triggers/) describes, and the Scene view handle of a contact.

### Only while [#only-while k=ad.ui.trigger.gate]

**Shown in:** Simple and Advanced: in the <Label k="ad.ui.advanced_fold" /> fold while it is <Label k="ad.ui.trigger.gate.always" />, in the panel once a toggle is picked · **Default:** <Label k="ad.ui.trigger.gate.always" /> · **Choices:** <Label k="ad.ui.trigger.gate.always" />, or any toggle on the avatar, with <Label k="ad.ui.trigger.toggle.on" /> or <Label k="ad.ui.trigger.toggle.off" />

A menu switch for the trigger: it works only while the chosen toggle is on, or off. <Label k="ad.ui.trigger.gate.always" /> means no such limit.

<Label k="ad.ui.trigger.gate.add" /> makes a new toggle named after the trigger, on by default, saved and synced, with no effects of its own. It sets the toggle as the trigger's <Label k="ad.ui.trigger.gate" /> and selects it in the tree, all in one step.

The scene preview and the wheel's Test mode respect <Label k="ad.ui.trigger.gate" /> too. On a contact trigger, the contact stays on the avatar while the switch is off: only its effects wait. On a blend shape trigger and a <Label k="ad.ui.touch.follow" /> contact, <Label k="ad.ui.trigger.gate" /> counts as one more requirement.

### Effects [#effects]

**Shown in:** Simple and Advanced · **Default:** <Label k="ad.ui.objects" />, empty · **Choices:** <Label k="ad.ui.objects" />, <Label k="ad.ui.blendshapes" />, <Label k="ad.ui.materials" />, <Label k="ad.ui.targets.properties" />, <Label k="ad.ui.targets.follows" />

A trigger has the same effect sections as a toggle, except <Label k="ad.ui.targets.animations" />. A trigger in <Label k="ad.ui.touch.flip" /> mode has none, and a blend shape trigger and a trigger in <Label k="ad.ui.touch.follow" /> mode have no <Label k="ad.ui.targets.follows" />. The sections are [Objects](../objects/), [Blend shape rows](../blend-shapes/), [Material slots](../material-slots/), [Material properties](../material-properties/) and [Follows](../toggle/#follows). <Label k="ad.ui.add_effect" /> adds a section. A trigger can also hold the rest of a mesh while it fires, with <Label k="ad.ui.shape_set.hold" />.

On means while the trigger fires, and off while it does not.

### Scene preview [#scene-preview k=ad.ui.preview]

**Shown in:** Simple and Advanced · **Default:** <Label k="ad.ui.preview.default" /> · **Choices:** <Label k="ad.ui.preview.default" />, <Label k="ad.ui.preview.on" />, <Label k="ad.ui.preview.off" />

<Label k="ad.ui.preview.on" /> shows the trigger's effects in the Scene view as if its condition were true. <Label k="ad.ui.preview.default" /> stops the preview.

### Platform [#platform k=ad.ui.platform]

**Shown in:** Simple and Advanced, in the <Label k="ad.ui.advanced_fold" /> fold · **Default:** <Label k="ad.ui.platform.inherit" /> · **Choices:** <Label k="ad.ui.platform.inherit" />, <Label k="ad.ui.platform.both" />, <Label k="ad.ui.platform.pc" />, <Label k="ad.ui.platform.quest" />

Which build makes the trigger. A trigger sits in no submenu, so <Label k="ad.ui.platform.inherit" /> takes the component's <Label k="ad.ui.platform" />.

## What AvatarDoc builds

At upload, a trigger adds one layer to the avatar's FX animator, named AD: and the trigger's name, with an off state and an on state. Its conditions become the moves between them. When the trigger changes a material property on an avatar with Write Defaults off, the layer also gets a Reset state, which it passes at load and on its way from on to off to set the property back to rest once; see [Explicit rests](../../how-it-works/layers-and-pins/#explicit-rests). It adds no parameter, no menu button and no synced bits: it reads parameters that already exist. A trigger with <Label k="ad.ui.seg.pin" /> rows or a rule that holds the rest puts those in a layer of its own, like a toggle.

A parameter trigger in <Label k="ad.ui.touch.follow" /> mode builds one layer instead, named AD:, the trigger's name and (follow): a resting state that writes no blend shape while the first parameter is 0 or another condition is false, and a blend from the effects' rest values to their full values over the parameter. It is built like a pin layer, at the end of the FX animator, in the place the trigger has among the other triggers.

When a trigger and a menu control change the same thing, the one AvatarDoc builds later wins. Triggers come after every menu control.
